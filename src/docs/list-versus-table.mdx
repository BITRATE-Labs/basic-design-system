# List versus table

**Use a list when each row is one main thing.** A row has a title, perhaps a line of detail, an icon and a trailing time or action, and people scan down the titles. Build it from the stock Item: `<ItemGroup data-variant="ruled">` draws one surface with hairline rules between the rows, so the rows are not boxes of their own. A selected row (`aria-current`, or `aria-selected` on an option) gets an inset rail and a step of ink; a checked row (the stock Checkbox inside it) gets a separate primary wash. See **Components / Item**.

**Use a table when rows are compared across columns.** If people read across a row and down a column (quantity, price, status, date), the values need to line up under a header, and the stock Table does that. It stays stock. See **Components / Table**.

Some guides:

- If a row would need column headers to make sense, it is a table.
- If you would hide most columns at phone width, it is probably a list with one line of detail.
- Do not put a ruled list inside another box. Inside a Card the card is the surface and the list goes flush; count the visible layers before adding one.
- Put a row's statuses and actions in the space beside its text rather than in a second line or a nested card. Secondary actions can be `<ItemActions data-reveal="hover">`: hidden until the row is hovered or focused where the pointer can hover, always shown on touch, and always reachable by keyboard.
