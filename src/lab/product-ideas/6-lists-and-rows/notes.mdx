# 6. Lists and rows

## Stock: a stack of Cards and the stock Table

Each row is its own ringed, rounded Card, or a Table row with a bottom border and a muted selected background. Selection and batch-checking look the same, and secondary actions are always visible.

## One-surface ruled list (drasil)

One bordered surface with rules between rows, a 4px selection rail that is always there but transparent (no layout shift), a separate primary wash for checked rows and a hover or focus-within lift; it comes from drasil's `.inbox-list` and `.inbox-row` (`globals.css`) and its "count visible layers" rule, with Chronote's inset-shadow rail and a smaller internal app's focus-within and 40rem wrap folded in. Adopting it is small to medium: unlayered theme CSS for list and table rows keyed on `aria-current`, `data-state="selected"` and the stock checkbox's `data-checked`, an Examples story, and the layer-count rule in AGENTS.md. The risks are that the rules use `--border`, which is strong in some brands (perkcord light is `#73868c`), and that the selected and checked washes lower the muted description below 4.5:1 where stock passes: basic light 3.76 to 3.80:1 against stock's 4.74:1, and chronote 2.82 to 2.99:1 against its already low 3.32 to 3.53:1.

## One-surface ruled list, adjusted for contrast

The same list with the muted description mixed halfway to `--foreground` on washed, hovered and focused rows. This is not drasil's rule. The lowest measured ratio becomes 4.64:1 (chronote dark), at the cost of a flatter title and description hierarchy on those rows.

## Hover-reveal secondary actions (Chronote)

Secondary row actions sit at opacity 0 with pointer events off and fade in over 120ms on hover or focus within the row, but only under `(hover: hover)`, so touch devices always see them; it comes from Chronote's Ask feedback buttons (`index.css`, `.ask-feedback-actions`). In the shipped product the fade does not render: Chronote's always-on colour-scheme rule (`html[data-mantine-color-scheme] #root *`, higher specificity) replaces the transition list and leaves out opacity, so the actions appear at once; the "Reveal timing" control shows both. Adopting it is tiny: one container and target attribute pair in shared CSS and a docs example. The risk is discoverability, so it suits secondary actions only.
